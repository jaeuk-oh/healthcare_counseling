# 보건소 의료비 지원 상담사 보조 AI

하남시 보건소의 의료비 지원 전화 상담을 돕는 도구다. 시민과 통화하는 건 사람 상담사고,
AI는 상담사 화면에 두 가지를 띄운다.

- **제안 답변** — 시민에게 그대로 읽어줘도 되는 문구
- **상담사 메모** — 왜 이렇게 안내하는지, 다음에 뭘 물어봐야 하는지, 전화로 판정하면 안 되는 항목은 뭔지 (시민에겐 안 보임)

상담사는 이 제안을 그대로 쓰거나, 고쳐 쓰거나, 버린다. 시민에게 뭐라고 말할지는 상담사가 정한다.

---

## 왜 만들었나

보건소 상담사에게 물어보니 "AI가 상담을 대신해줬으면 좋겠다"가 아니라 "AI가 옆에서 도와줬으면 좋겠다"였다.
그래서 AI가 시민에게 직접 답하는 챗봇이 아니라, 상담사가 검수하는 보조 도구로 방향을 잡았다.

의료비 상담은 틀리면 그냥 "답이 별로"인 정도로 끝나지 않는다.

- 자격이 안 되는데 "될 것 같다"고 하면 → 시민이 서류 챙겨서 보건소 갔다가 헛걸음한다.
- 될 수 있는데 "안 된다"고 하면 → 받을 수 있는 지원을 그냥 놓친다. 이쪽이 더 나쁘다.

그리고 소득·재산 같은 항목은 애초에 전화로는 판정할 수 없다. 서류를 봐야 안다.
문제는 LLM이 대화 맥락만 보고 "소득 기준 충족하신 것 같네요"라고 쉽게 단정한다는 거다.
LLM의 유연함이 여기서는 그대로 위험이 된다.

그래서 판단 자체는 LLM에 맡기되, **틀렸을 때 시민이 실제로 손해 보는 지점만 코드로 막는** 쪽으로 만들었다.

---

## 어떻게 만들었나

### 검색을 안 쓰는 RAG

RAG 형태를 빌렸지만 검색의 선별 기능은 안 쓴다. 대상 정책 문서가 3개뿐이라 고를 게 없다.
매 턴 문서 전체를 컨텍스트로 넣는다 (`top_k = 문서 수`). 3개짜리 문서에 벡터 검색으로
"관련 있는 것만 골라주는" 로직을 얹는 건 없는 문제를 푸는 거였다.
실제 지능은 검색이 아니라 체크리스트를 한 항목씩 채워가는 상태 관리에 있다.

```
시민 발화
  → classify()   : 해당될 만한 정책 선별 (암의료비 / 희귀질환 / 국가암검진)
  → 선별된 정책의 체크리스트를 전부 '미확인'으로 초기화
  → 매 턴: LLM 한 번 호출로 [제안 답변 + 상담사 메모 + 체크리스트 갱신]
  → 코드 가드레일 적용 (아래)
  → 상담사가 채택 / 수정 / 무시  →  최종 발화
```

### LLM에 맡기면 사고 나는 지점 3개를 코드로 막았다

각각 실제로 겪은 문제에 대한 대응이다.

**1. 소득·재산은 LLM이 뭐라 하든 '미확인'으로 고정한다.**
LLM이 대화만 보고 "소득 기준 충족"으로 단정하는 게 반복됐다. 이 항목들은 서류로만 확인되는데도.
그래서 체크리스트 항목마다 `confirmable_by: phone | visit` 플래그를 두고, `visit` 항목은
LLM 출력을 무시하고 코드에서 항상 미확인으로 덮어쓴다. 상담사 메모에는 "이건 전화로 판정 말고
내방 유도"라고 띄운다.

**2. 근거와 결론이 어긋나면 결론을 코드가 고친다.**
건강보험 가입자는 2021.7.1부터 신규 지원이 끊겼다. 그런데 LLM이 근거에는 "신규지원 중단"이라고
써놓고 결론은 "지원 가능"으로 내는 일이 계속 있었다. 프롬프트로 "근거랑 결론을 맞춰라"라고
지시해도 샜다. 그래서 근거 텍스트에 "지원 불가 / 신규지원 중단" 같은 키워드가 있으면
결론을 코드에서 강제로 `false`로 바꾼다. 프롬프트로 못 잡은 걸 후처리로 잡은 셈이다.

**3. 이미 확정된 항목은 되돌리지 못하게 막는다.**
`true`/`false`로 굳은 항목을 LLM이 다음 턴에서 `null`로 되돌리는 경우가 있었다.
대화가 길어질수록 상태가 흔들려서, 확정값은 코드에서 잠갔다.

### 삼분법 — 처음 만든 게 틀렸던 부분

처음엔 "건강보험 가입자 = 지원 불가"로 단순하게 짰다. 건보가입자라는 게 확인되면
바로 상담을 끝냈다.

그런데 이게 틀렸다. 2021.6.30 이전에 국가암검진을 받았고 + 2023.6.30 이전에 진단받았고 +
보험료 기준을 충족하면 건보가입자도 지원되는 케이스가 실제로 있었다. 이걸 모르고
"건보가입자시네요, 안 됩니다"로 끊어버리면 되는 사람을 돌려보내는 거다. 앞에서 말한
"될 수 있는데 안 된다고 하는" 제일 나쁜 경우다.

그래서 즉시 종료를 없애고, 건보가입자면 수검일·진단일을 더 물어보는 분기를 넣었다.
체크리스트 라벨도 "(건강보험 가입자만)"으로 조건을 드러내서, 의료급여 수급자한테는
이 항목들을 건너뛰게 했다. 상담 프로세스의 분기를 체크리스트 구조가 그대로 따라가도록.

### 크롤링만으로는 안 됐다

정책 문서는 보건소·질병관리청 사이트를 크롤링해 GPT로 마크다운으로 정리했다.
그런데 요약 과정에서 위의 "2021.7.1 신규지원 중단" 같은 핵심 조건이 통째로 빠졌다.
문서에 조건이 없으니 시스템은 건보가입자한테 그냥 "됩니다"라고 안내했다.
결국 현장에서 확인한 조건들을 문서에 직접 박아 넣어야 했다. 공개 문서 크롤링으로
얻을 수 있는 건 뼈대까지고, 상담 품질을 가르는 조건은 사람이 아는 걸 넣어야 나왔다.

### 국가암검진 시나리오를 잘못 이해했던 것

국가암검진 테스트 시나리오를 처음엔 "암 진단받고 지원 문의"로 만들었다. 그런데 실제
국가암검진 전화는 그게 아니었다. 검진 통보서(안내 우편)를 받은 사람이 "어느 병원 가서
받으면 되냐"고 묻는 거였다. 페르소나가 틀리니 검증 자체가 엉뚱한 걸 재고 있었다.
프리셋 질문을 실제 문의 형태로 고쳤다.

### 상담사가 고친 걸 데이터로 남긴다

AI 제안은 시민에게 바로 안 나간다. 상담사가 채택(accepted) / 수정(edited) / 무시(rejected)
중 하나를 고르고, 그 내역이 `/suggestion-feedback`로 저장된다 (Supabase, 없으면 로컬 JSONL).

이걸 남기는 이유는 감사(audit) 때문이 아니다. **상담사가 제안에서 뭘 빼고 뭘 보탰는지가
곧 "AI가 어디서 자주 틀리는지"의 신호**라서다. `scripts/analyze_feedback.py`가 제안과
상담사 최종본을 `difflib`로 비교해서:

- 상담사가 자주 **뺀** 표현 → AI가 과하게 말하는 지점 (위 2번 같은 가드레일 키워드 후보)
- 상담사가 자주 **보탠** 표현 → AI가 빠뜨리는 정보 (문서·프롬프트 보강 후보)
- 통째로 **무시된** 제안 → 방향이 틀린 케이스

를 빈도순으로 뽑는다. 지금 가드레일 키워드는 내가 로그를 눈으로 보고 손으로 넣었는데,
그 과정을 로그에서 반자동으로 뽑아내려는 시작점이다. (아직 후보를 실제 가드레일에
반영하는 건 수작업이다.)

### 그 외 결정 몇 개

- **서버는 대화 상태를 저장 안 한다.** `/chat`이 매 턴 전체 대화 이력과 체크리스트를
  클라이언트한테 받는다. 대화가 10턴 안쪽으로 짧고 병목은 LLM 응답 시간이라, 세션
  스토어를 두는 복잡도가 남는 게 없었다. eval도 같은 이유로 Python 변수로 상태를
  들고 멀티턴을 돌린다.
- **LangChain을 안 썼다.** 문서 3개에 체크리스트 상태 머신이 핵심인데, 체인·리트리버
  추상화를 얹으면 정작 중요한 function calling 스키마와 후처리 분기가 프레임워크
  뒤로 가려진다. OpenAI SDK를 직접 호출하는 게 코드가 더 읽혔다.
- **지도 기능은 넣었다가 뺐다.** 초기엔 보건소 위치를 지도로 보여줬는데 상담 흐름에
  도움이 안 됐다. 빼면서 남아 있던 의존성(`react-leaflet`)도 정리했다.

## 잘 되나

두 종류로 검증한다. `/query`(정책 분류)는 10개 시나리오, `/chat`(멀티턴 상담)은 5개.

**정책 분류 — 8/10**

10개 중 8개는 맞고, 틀린 2개는 이렇다.

- **S03**: "국가암검진을 받았고 위암 진단" 쿼리를 국가암검진으로 오분류한다.
  문장에 "국가암검진"이라는 단어가 있으니 그쪽으로 끌려간다. 삼분법으로 잡아야 할
  성인암 케이스인데 놓친다.
- **S09**: 국가암검진 통보서 문의(어느 병원 가냐)를 지원 신청으로 못 보고 빈 응답을 낸다.

둘 다 "분류기가 표면 키워드에 약하다"는 같은 뿌리다. 위에서 페르소나를 고쳐서
데이터는 맞췄지만, 분류 프롬프트 자체는 아직 못 고쳤다.

**멀티턴 상담 — 5/5**

- C01 성인암 의료급여 수급자 → 내방 안내 (1턴)
- C02 성인암 건보, 수검일 미충족 → 지원불가 + 대안 안내 (2턴)
- C03 성인암 건보 삼분법, 수검일·진단일 순서대로 확인 후 내방 (3턴)
- C04 소아암 의료급여 당연선정 → 내방 안내 (1턴)
- C05 희귀질환 파브리병, KCD 확인 후 내방 안내 (1턴)

위에서 만든 가드레일(소득 동결, 확정값 잠금, 삼분법 분기)이 실제 대화 흐름에서
작동하는지를 본다. C03가 3턴 걸리는 건 정상이다 — 건보가입자면 수검일·진단일을
순서대로 물어야 하니까.
